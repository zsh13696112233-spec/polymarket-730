# PolyCopy｜Polymarket 链上资金监测与跟单控制台

PolyCopy 是一个本地运行的 Polymarket 链上大额资金监测、策略决策和交易管理控制台。
系统持续采集公开成交与市场数据，识别值得关注的巨鲸信号，并在同一套账本中管理手动跟单、
自动跟单、卖出、对账和结算赎回。

> 本项目包含真实资金交易能力。首次运行或只做界面、数据验证时，请先将
> `POLYMARKET_TRADING_ENABLED` 设为 `0`。不要将 API 直接暴露到公网，也不要使用存有主要资产的
> 钱包作为执行钱包。

## 当前能力

### 链上信号监测

- 在固定的 24 小时成交窗口内运行两套规则：

  - **新号大额**：仅关注注册时间处于配置窗口内的新账户。
  - **全量超大额**：不限制账户年龄，按钱包、市场和 outcome 累计买入金额。
- 结合公开档案、市场标签、当前持仓与买卖流水，区分仍在持有、已退出和对冲状态。
- 按市场聚合多钱包信号，展示相同方向与相反方向的资金分歧。
- 永久保留规则触发历史；账户加入排除名单后停止监测和统计，但不删除底层历史或真实交易账本。
- 提供手动扫描、扫描状态、失败信息和实时请求监控。

监测条件支持传统体育、电竞、政治、加密、科学与科技、娱乐和其他多选，默认全选，至少选择一类。两条规则共用监测分类，自动跟单仍独立校验自身允许分类。调整监测分类同时控制新机会和当前监测列表：未选分类的已有机会隐藏，重新勾选后符合条件的记录恢复；底层历史和已有持仓继续保留与更新，首页历史统计不按当前分类追溯过滤。

监测质量与补充覆盖：

- 仍有仓位但当前份数低于窗口买入份数的保留比例门槛（默认 80%）时，显示“已减仓”，暂停跟单资格。这个比例是相对采集窗口的参考值，不是完整账户历史的卖出比例；页面同时展示独立核验的剩余成本、估值和时间。
- 对冲根据同一市场的当前仓位核验，即使反向买入发生在采集窗口外也会识别。双向持仓不作为单边可跟信号；二元市场显示扣除反向份数后的净方向份数。
- 相同钱包、市场、买入记录的持仓快照最多缓存 5 分钟；出现新买入或缓存到期时刷新，命中缓存不会改写实际核验时间。预览和执行跟单都独立重新核验来源钱包，减仓、退出、对冲或查询失败时阻止下单。
- 市场分类在查询候选钱包资料前过滤。补充发现每 15 分钟从成交量靠前的 100 个可交易市场中筛选符合监测分类的最多 20 个重点市场，每轮处理最多 2 个，正常完成的市场至少间隔 15 分钟。
- 重点市场额外查询无单笔金额门槛的买单，实际发送 `start/end`。首次补齐统计窗口，之后从各市场已完成进度回叠 120 秒做增量采集；读满的区间按整秒二分，同秒成交继续分页。单市场每轮最多处理 4 页查询（每页 500 条，仍受扫描页数配置限制，失败沿用原有重试），待补区间和暂存成交持久化，未完成任务至少间隔 60 秒续跑，正常完成后间隔 15 分钟。整个批次完整后才原子并入信号并推进覆盖进度，按原有交易标识去重；首次或跨轮历史补齐仅限制实际新增历史成交对应的钱包和方向，不影响其他主扫描信号；历史发现不会直接触发自动买入，也不会消耗后续真实新买入的首次自动决策机会。升级会恢复上一版被历史限制拦截的状态，但不会重放已经记录的旧买入。正常补齐在首页显示降级状态，未检查该市场的轮次不会清除提示；接口越界、重复分页或同秒超出分页容量仍保留异常和缺口，不宣称全市场、全量拆单覆盖。
- 同时查询重点市场按 token 数量排列的前 20 个持仓记录，过滤没有历史买入的异常余额，并逐钱包核验。没有近期成交的记录标注“持仓补充发现”，买入时间未知；这类发现不会自动买入，也不会单独触发交易分歧锁。后续真实买入满足规则时才进入原有自动决策流程。

### 信号统计与通知

- 按规则、市场分类、金额层级和时间范围统计已结算信号的命中率与理论收益。
- 展示整体表现、分类表现、趋势、资金加权盈亏平衡线和逐条结算明细。
- 支持新信号、同市场方向分歧和每周命中率汇总邮件。
- 邮件记录按收件人展示排队、发送、重试和失败状态；SMTP 授权码可保存在 macOS 钥匙串中。

### 真实跟单与持仓管理

- 从链上信号生成盘口预览，并通过一次性确认信息执行真实买入或卖出。
- 为“新号大额”和“全量超大额”分别配置自动跟单开关、基础单笔金额、实际买价区间、可选低价小额档和允许的市场分类。
- 可选启用“双重命中跟单金额”：首次自动决策时，同一来源钱包、同一市场方向同时命中两条规则，独立金额覆盖基础档与低价档；仍沿用所选策略（符合开关和分类条件时全量超大额优先）的价格区间及现有交易限制。默认关闭，后续新增命中不补买。
- 两类策略按同一市场（`condition_id`）共享最大购买次数与累计投入上限，仅统计自动跟单买入本金，不含手续费；待确认订单预占额度，未成交释放，卖出后不重置生命周期累计值。不同市场独立计数，同一赛事的多个市场不会合并限额。
- 自动跟单记录每次策略决策、跳过原因、成交结果和风控退出结果。
- 自动决策列表和首页将价格区间、来源双向持仓或减仓退出、市场关闭、金额与余额限制等已知拦截显示为黄色“策略保护”，历史记录同样适用；接口限流、网络或执行异常仍显示“执行失败”。状态筛选使用相同口径，原始决策与订单记录不变。
- 普通手动跟单和自动跟单校验单笔金额上限、余额与手续费、来源持仓及市场状态。**当前账户预算、现金储备、总敞口、每日买入和每日亏损限额仅在“链上环境测试买入”中强制执行，尚未接入普通跟单与自动跟单；现金储备在普通跟单预览中仅作警告。** 不应依赖这些账户配置限制自动跟单的全局投入。
- “我的跟单”展示跟单汇总、买卖流水、费用、已实现盈亏、卖出和赎回结果；当前持仓查看和手动卖出统一使用“持仓管理”。
- “系统设置”提供链上环境测试工具，可从官方市场链接识别 outcome，以小额真实买入并在成交后预览、确认卖出本次成交份额。
- 已有跟单周期中的 Polymarket 外部手动买卖会自动归集并对账；重复扫描通过事件指纹保持幂等。
- 已结算持仓支持自动赎回到 pUSD，必须同时开启执行账户和巨鲸设置中的 `auto_redeem`。此路径不受 `POLYMARKET_TRADING_ENABLED` 控制。存在无法归因的同市场 outcome token 或提交状态不确定时，
  系统会停止重复提交并转为人工检查。

### 首页总览

- 展示 API、数据库、扫描器和两套监测规则的运行状态。
- 分别展示新号大额、全量超大额最近 1、3、5、7 天链上发现机会数：北京时间自然日且包含今天，每条规则按钱包、市场和方向在该规则下的首次触发去重；双规则命中各计一次，排除名单内账户不计入。
- 汇总跟单投入、回收、费用、已实现盈亏和近 7/15/30 日趋势。
- 展示执行钱包余额、风险状态、最近自动跟单决策和实时请求流。

## 当前产品边界

项目已经移除手工添加固定钱包的轮询、持仓分析和固定钱包自动跟单接口。当前监测与执行链路是：

```text
Polymarket 公开成交与市场数据
  → 共用监测市场分类筛选
  → 新号大额 / 全量超大额规则
  → 当前持仓核验与信号历史
  → 手动预览确认或自动策略决策
  → 统一交易执行器
  → 持仓、流水、对账与赎回
```

后续自动化应继续消费链上监测信号并复用现有交易执行器，不应重新引入固定钱包轮询链路。

## 技术架构

- **Web**：Next.js 16、React 19、TypeScript、vinext、Vite、Vitest。
- **Worker 构建**：Cloudflare Worker 入口位于 `worker/index.ts`，项目包含 Sites 托管配置。
- **API**：Python 3.12、FastAPI、SQLAlchemy Async、HTTPX。
- **数据**：SQLite（默认）与 Alembic；API 启动时自动升级到最新数据库版本。
- **交易**：`polymarket-client==0.7.1`，当前仅支持 Deposit Wallet（`signature_type=3`）。
- **凭证**：执行私钥、Builder 凭证和界面保存的 SMTP 授权码使用 macOS Keychain。

项目主要目录：

```text
app/                         Next.js 页面与 React 工作台组件
backend/main.py              FastAPI 应用、生命周期与 HTTP 接口
backend/polymarket.py        Polymarket 公开数据与市场客户端
backend/whale.py             扫描、规则、跟单、对账与赎回逻辑
backend/trading.py           统一 SDK 交易与链上执行边界
backend/models.py            SQLAlchemy 数据模型
backend/schemas.py           API 请求与响应模型
backend/alembic/versions/    数据库迁移
backend/tests/               Python 后端测试
tests/                       Web 单元测试与渲染测试
docs/                        设计与实施记录
worker/index.ts              vinext Cloudflare Worker 入口
```

## 运行要求

- macOS（真实交易和界面管理的 SMTP 凭证依赖系统钥匙串）
- Node.js 22.13 或更高版本
- Python 3.12 或更高版本
- `uv`
- 可访问 Polymarket Data API、Gamma API、CLOB API、Polygon RPC；真实钱包操作还会使用 Relayer API

依赖分别由 `package-lock.json` 和 `uv.lock` 锁定，请使用 `npm` 与 `uv`，不要混用其他包管理器。

## 安装与配置

安装依赖：

```bash
npm ci
UV_CACHE_DIR=.uv-cache uv sync
```

如果项目根目录还没有 `.env`，复制示例配置：

```bash
cp .env.example .env
```

首次启动前，建议先在 `.env` 中设置：

```dotenv
POLYMARKET_TRADING_ENABLED=0
```

开发和生产启动命令均监听 `0.0.0.0`（前端 `3000`、后端 `8730`）。内网访问时，在 `.env` 中将 `NEXT_PUBLIC_API_BASE` 设为 `http://服务器内网IP:8730`，将 `POLYMARKET_CORS_ORIGINS` 设为 `http://服务器内网IP:3000`，然后重启服务，通过 `http://服务器内网IP:3000` 访问。仅在可信内网使用；CORS 不是身份认证，不能阻止非浏览器客户端调用 API。生产模式需重新构建前端；内网 IP 变化后需同步更新这两个配置。

常用环境变量：

| 变量 | 用途 |
| --- | --- |
| `NEXT_PUBLIC_API_BASE` | Web 访问 FastAPI 的基础地址，默认 `http://127.0.0.1:8730` |
| `POLYMARKET_CORS_ORIGINS` | 额外允许的前端来源，多个地址用逗号分隔；始终保留默认本机来源 |
| `POLYMARKET_DATABASE_URL` | SQLAlchemy 数据库地址，默认写入 `data/polymarket-watch.db` |
| `POLYMARKET_TRADING_ENABLED` | 新的真实买入、卖出开关；`0` 阻止手动及自动买卖，不关闭自动赎回或已有订单对账 |
| `POLYMARKET_PROXY_URL` | Polymarket API 与 Polygon RPC 强制使用的 HTTP(S) 代理，默认 `http://127.0.0.1:7897` |
| `POLYMARKET_WHALE_ENABLED` | 链上巨鲸扫描模块总开关 |
| `POLYMARKET_WHALE_SCAN_INTERVAL_SECONDS` | 后台扫描间隔 |
| `POLYMARKET_WHALE_MAX_SCAN_PAGES` | 每轮扫描最多读取的成交分页数 |
| `POLYMARKET_*_API_CONCURRENCY` | Data、Gamma 与 CLOB 客户端并发上限 |
| `POLYMARKET_CLOB_API_URL` | CLOB API 地址 |
| `POLYMARKET_RELAYER_API_URL` | 钱包操作使用的 Relayer API 地址 |
| `POLYMARKET_POLYGON_RPC_URL` | Polygon RPC 地址 |
| `POLYMARKET_SMTP_*` | SMTP 的主机、端口、账号、发件人和安全模式 |

`POLYMARKET_START_MONITOR=0` 也可用于本地调试：它会阻止后台扫描器和邮件发送器随 API 启动；已有跟单买卖及钱包手动订单的后台对账仍运行，手动请求接口也不会因此停用。

订单提交前会保存可用于交易所查询的 V2 订单哈希。提交响应丢失时，后台每 10 秒尝试核对已保存标识的待确认订单，核对过程不会重新下单；查询失败或暂时查不到时继续保留待确认状态与预占额度。旧版本因手续费查询失败而丢失订单 ID 的记录，会使用原始错误中保留的精确成交 ID 找回订单，核对钱包归属、市场、方向、时间和限价后补账；找回标识会先保存，手续费仍失败时继续等待对账。历史 FAK 订单查询返回空值时，会分页核对该订单的完整已确认成交；归属、时间、价格或总额不一致时保留待对账。最近核对失败原因会更新到订单及跟单决策提示中。没有精确成交线索或核对不一致的旧记录仍需人工核对。

## 本地运行

同时启动 Web 和 API：

```bash
npm run dev:all
```

后端会强制通过 `POLYMARKET_PROXY_URL` 访问 Polymarket 和 Polygon RPC；代理不可用时请求失败，不会回退直连。

打开 [http://localhost:3000](http://localhost:3000)。API 健康检查地址是
[http://127.0.0.1:8730/healthz](http://127.0.0.1:8730/healthz)。

只启动单个服务：

```bash
npm run dev
npm run dev:api
```

如果只需要安全地检查界面和本地服务，不希望后台扫描或实盘执行：

```bash
POLYMARKET_TRADING_ENABLED=0 POLYMARKET_START_MONITOR=0 npm run dev:all
```

默认 SQLite 文件存放在 `data/`。巨鲸请求或持仓核验失败会追加到同目录的
`whale-failures.jsonl`，单文件上限 5 MiB，并保留 3 个轮转备份。该目录、`.env`、缓存和
构建产物均已被 Git 忽略。

## 配置执行钱包

当前执行层仅支持 Deposit Wallet。先在“系统设置”页面填写签名钱包和资金钱包地址，再将签名钱包私钥
写入 macOS 钥匙串：

```bash
uv run python -m backend.trading_cli set-key --account 0xYourSigningWalletAddress
```

命令会要求输入两次私钥，输入内容不会回显。私钥不会写入 `.env`、数据库、API 响应或日志。

如需 Builder 凭证支持的 gasless 钱包操作，可单独写入同一签名账户对应的钥匙串记录：

```bash
uv run python -m backend.trading_cli set-builder-creds --account 0xYourSigningWalletAddress
```

配置完成后，在“系统设置”中执行“验证密钥与授权”和“刷新余额”。确认签名地址、Deposit Wallet 类型、
pUSD 余额及 V2 Exchange 授权都正确，再按需开启 `POLYMARKET_TRADING_ENABLED=1`。自动跟单策略仍需在
“自动跟单”页面单独开启。

## 跟单金额与风险口径

- 新号大额与全量超大额的金额是固定买入本金，不按来源钱包买入比例缩放。手续费另计，最低可下单金额按盘口最小份数和最差成交价计算。
- 设置低价档后，实际卖一价严格低于分界价时使用低价金额；等于分界价时使用基础金额。执行时价格跨档会拒绝旧预览，不自动加大金额。
- 同一钱包、同一资产只做一次自动决策；历史补齐和纯持仓补充发现等待后续新买入，不能作为立即补买理由。
- 评估金额时应同时比较投入预算、实际现金、同市场最大累计本金、相关市场集中度和已结算实盘表现。信号命中率和理论收益不等于自己的扣费实盘收益。
- 当前缺少普通跟单的全局预算、敞口和每日限额拦截；单市场上限不能替代这些保护。每日亏损字段也不是保证最大亏损的止损单。
- 用户实时金额与余额保存在本地数据库，不写入通用文档；模型默认值不代表用户当前配置。

## 安全说明

- 本项目设计为本机控制台，不提供面向公网部署所需的用户认证和多租户隔离。
- 私钥、Builder secret、passphrase、完整签名内容和 SMTP 授权码不得进入源码、数据库或日志。
- `POLYMARKET_TRADING_ENABLED=0` 是新的真实买入与卖出的紧急开关，不替代钱包隔离和资金限额。
- 自动跟单是真实资金功能；价格分档、单市场次数与金额上限、分类过滤、敞口限制和每日限额不应被绕过。
- 交易提交、链上确认或赎回结果不确定时，不要盲目重试；系统会保留状态用于对账或人工检查。
- 不要通过删除 `data/` 数据库来处理扫描或迁移问题，否则会丢失信号历史、执行账本和幂等状态。

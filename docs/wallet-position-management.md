# 执行钱包持仓管理

工作台的「持仓管理」（`/positions`）只展示默认执行钱包的未结算持仓，包括外部买入。
不展示钱包地址，不提供搜索或状态筛选。已结算持仓和零价值结算份额不在此页展示。
不新增手动赎回，原有自动赎回行为保持不变。

## 一键卖出

点击一笔持仓的「一键卖出」，系统自动读取全部可卖份额和实时价格，展示数量、
价格下限、预计金额、手续费及可计算的盈亏。点击「确认真实卖出」后才提交。
无需填写价格、数量、比例或确认文案；取消确认不会下单。

交易沿用系统现有 `polymarket-client==0.7.1` 的 `AsyncSecureClient`，只创建 FAK
卖单：立即成交，未成交余量自动取消，不创建新的持续挂单。份额按 SDK 两位小数
向下取整，保留现有滑点和最小下单量检查。

卖出预览接口只接受全部可卖份额及 FAK，拒绝限价或指定部分份额。确认令牌五分钟
有效、单次使用，绑定账户及操作。页面确认按钮发送固定确认文案，后端继续严格校验。
令牌过期或提交失败后不能自动重新下单，订单使用持久化幂等键防重复提交。

## 对账和历史记录

可卖份额取核验一致的链上/CLOB 余额，扣除 SDK 完整分页查到的已有卖单及本地
未终结卖单，按上游订单 ID 去重。余额、持仓、挂单或结算状态不一致时暂停卖出。
旧卖出入口及自动卖出使用相同的占用校验。数据接口持仓份额可能截断至四位小数，
小于 0.0001 份的索引精度差不阻止卖出；数量仍取核验一致的链上/CLOB 余额，
链上与 CLOB 之间的微单位校验不变。两个余额都确认为零且无占用时，不展示索引残留记录。
页面的「卖出订单」默认折叠，仅供查看结果。

保留历史订单数据、旧 GTC 订单对账和撤单接口，以处理简化前可能已经存在的订单。
页面不再提供限价挂单或撤单操作，已有订单不会因界面简化而自动取消或释放占用。
已知上游订单 ID 的本系统订单每十秒对账，不依赖链上扫描开关，重启后继续处理。
在收到上游订单 ID 前崩溃或超时的订单保持待核对状态，不盲目重提或释放占用。

纯外部持仓不创建跟单周期；关联跟单仓位的确认成交写入原账本，来源为
`wallet_manual`，通过成交指纹和交易哈希避免重复归集。存在未完成订单时不能切换钱包。

## 自动止盈

「持仓管理」提供按钱包保存的自动止盈开关和兑付比例阈值，默认关闭、阈值为 90%。
首页「运行概览」显示当前执行钱包的自动止盈开关状态，并提供止盈设置入口；
首页数据读取失败或实时连接中断时显示「状态待确认」，不把旧状态当作当前状态。
开启后先完整读取现有持仓作为基线，现有仓位由用户逐笔加入保护；此后钱包新增的
持仓自动加入，包括外部买入。重新开启时，关闭期间新增的仓位作为现有持仓处理。
同一未清空仓位的加仓沿用该仓位保护状态；完整快照观察到清空后再次出现，按新仓位处理。
读取不完整不能开启策略或更新基线。切换钱包不继承其他钱包的策略设置。

触发条件是全部可卖份额的净回款达到最高兑付额的设定比例，且扣除预估卖出费用后
高于对应成本。订单簿深度必须足以支持全部可卖份额，限价同时满足止盈比例、盈利、
价格步进和既有滑点下限。页面门槛只是按可卖份额换算的提示，不代表保证成交金额。
本系统成本沿用含已记录买入费用的账本；纯外部持仓使用公开平均买价，并核对其与
公开持仓成本一致，不含未记录的历史买入费用。缺失或矛盾的数据不能触发自动卖出。

后台每轮完成后间隔 10 秒检查，不依赖页面是否打开；新的自动卖出同时受策略开关、
`POLYMARKET_TRADING_ENABLED` 和 `POLYMARKET_START_MONITOR` 控制。策略开启即授权满足
条件时自动卖出，不逐笔弹确认框。手动卖出继续使用原有预览与确认流程。

自动卖出来源为 `auto_take_profit`，复用钱包 FAK 执行器、份额占用、幂等和对账。
部分成交后只重新判断剩余份额，提交结果不明时等待对账，不重复下单。准备提交的
订单与策略／成本快照在同一事务保存，重启后仍保留占用。自动止盈订单处理期间
阻止该钱包同方向自动买入；首次确认成交后，该市场同方向不再自动买回，关闭止盈
或手动买入也不清除这一标记。该标记不限制手动买入，不影响其他方向或钱包。

## 自动止盈效果统计

「我的跟单」增加当前钱包全部时间的独立止盈统计，包含外部买入后自动卖出的仓位，
不受普通流水日期筛选影响，不为外部持仓创建跟单周期，也不重复计入原有跟单汇总。
每条明细对应一笔卖出订单，只使用确认成交份额及其实际卖出费用；费用或成交待核对
时金额显示待核对，不能当成零手续费。金额按 USDC 六位精度汇总。

- 已实现止盈利润：卖出净回款减对应记录成本；外部均价成本的限制在页面明确说明。
- 保住回款：净回款高于同份额最终兑付额的差额。
- 少赚金额：同份额最终兑付额高于净回款的差额。
- 提前卖出净影响：累计保住回款减累计少赚金额。

尚未最终结算的成交仅计入止盈利润和待结算笔数，不提前计算保住／少赚金额。
例如成本 40、净卖回 64、最高兑付 70，止盈利润为 24；最终输则保住回款 64，
最终赢则少赚 6。保住回款不是交易利润，比较基准是继续持有到最终结算。

后台至少间隔 60 秒核验待结算市场，沿用明确 `resolved`／`finalized` 的结算资料，
支持特殊兑付比例；普通中途价格不能充当结算结果。已清仓市场通过保存的市场 ID
继续核验，修改阈值不改写历史快照，重复对账不重复累计。此核验不触发赎回。
关闭策略或交易开关后，已有成交仍可核验结算；关闭后台监测则暂停结算资料查询，
既有钱包订单的后台对账仍保持原有规则。

## 接口和迁移

接口位于 `/api/execution-account`：

- `GET /positions`：钱包、持仓和卖单。
- `GET /orders`：卖单列表。
- `POST /positions/{asset_id}/sell/preview`、`POST .../execute`。
- `GET /take-profit`、`PUT /take-profit`：钱包止盈设置和运行状态。
- `PUT /positions/{asset_id}/take-profit`：加入或退出保护。
- `GET /take-profit/statistics?limit=20&offset=0`：汇总及分页明细。

金额、价格和份额返回十进制字符串。保留迁移 `0043_wallet_position_orders` 及历史
订单类型，不回滚或改写已应用的迁移。新增 `0049_auto_take_profit` 保存止盈策略、
持仓保护及执行快照，不改写现有订单历史。设置写入携带钱包地址，旧页面不能误改
切换后的钱包；阈值允许最多两位小数，必须大于 0 且小于 100。

验证使用模拟 SDK 与临时数据库，不提交真实订单或授权。

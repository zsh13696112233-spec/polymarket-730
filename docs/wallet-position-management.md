# 执行钱包持仓管理

工作台的「持仓管理」（`/positions`）只展示默认执行钱包的未结算持仓，包括外部买入。
不展示钱包地址，不提供搜索或状态筛选。已结算持仓和零价值结算份额不在此页展示。
不新增手动赎回，原有自动赎回行为保持不变。

## 一键卖出

点击一笔持仓的「一键卖出」，系统自动读取全部可卖份额和实时价格，展示数量、
价格下限、预计金额、手续费及可计算的盈亏。点击「确认真实卖出」后才提交。
无需填写价格、数量、比例或确认文案；取消确认不会下单。

交易沿用系统现有 `polymarket-client==0.7.1` 的 `AsyncSecureClient`，只创建 FAK
卖单：立即成交，未成交余量自动取消，不创建新的持续挂单。份额按 SDK 两位小数
向下取整，保留现有滑点和最小下单量检查。

卖出预览接口只接受全部可卖份额及 FAK，拒绝限价或指定部分份额。确认令牌五分钟
有效、单次使用，绑定账户及操作。页面确认按钮发送固定确认文案，后端继续严格校验。
令牌过期或提交失败后不能自动重新下单，订单使用持久化幂等键防重复提交。

## 对账和历史记录

可卖份额取核验一致的链上/CLOB 余额，扣除 SDK 完整分页查到的已有卖单及本地
未终结卖单，按上游订单 ID 去重。余额、持仓、挂单或结算状态不一致时暂停卖出。
旧卖出入口及自动卖出使用相同的占用校验。数据接口持仓份额可能截断至四位小数，
小于 0.0001 份的索引精度差不阻止卖出；数量仍取核验一致的链上/CLOB 余额，
链上与 CLOB 之间的微单位校验不变。两个余额都确认为零且无占用时，不展示索引残留记录。
页面的「卖出订单」默认折叠，仅供查看结果。

保留历史订单数据、旧 GTC 订单对账和撤单接口，以处理简化前可能已经存在的订单。
页面不再提供限价挂单或撤单操作，已有订单不会因界面简化而自动取消或释放占用。
已知上游订单 ID 的本系统订单每十秒对账，不依赖链上扫描开关，重启后继续处理。
在收到上游订单 ID 前崩溃或超时的订单保持待核对状态，不盲目重提或释放占用。

纯外部持仓不创建跟单周期；关联跟单仓位的确认成交写入原账本，来源为
`wallet_manual`，通过成交指纹和交易哈希避免重复归集。存在未完成订单时不能切换钱包。

## 接口和迁移

接口位于 `/api/execution-account`：

- `GET /positions`：钱包、持仓和卖单。
- `GET /orders`：卖单列表。
- `POST /positions/{asset_id}/sell/preview`、`POST .../execute`。

金额、价格和份额返回十进制字符串。保留迁移 `0043_wallet_position_orders` 及历史
订单类型，不回滚或改写已应用的迁移。本次简化不需要新的数据库迁移。

验证使用模拟 SDK 与临时数据库，不提交真实订单或授权。
